# Low memory ARPC

`arpclm.cu` is a CUDA, multi-GPU implementation of the low-memory
accelerated randomly pivoted Cholesky (ARPC-LM) method for the low
rank approximation of kernel matrices.

The code stores only the `rmax x rmax` inverse Cholesky factor `L^{-1}`
and regenerates kernel matrix entries on demand.
The kernel entries are computed in `rblk x rmax` blocks,
which means that no `NM x rmax` factor matrix is ever formed.
As a result, storage is `O(NM + rmax^2)` rather than `O(NM rmax)`,
at the cost of raising the number of kernel evaluations to `O(NM rmax^2)`.
The regeneration loop is the dominant cost of a run.

The method is run for a fixed number of rounds `Nrounds`, with each
round proposing a block of `BLK` candidate pivots.
The realized rank `Nr` is an output of the code, not an input:
the proposed `rmax = Nrounds * BLK` is only an upper bound, and the
number of pivots accepted per round varies.

## What the code computes

Per round `i` we compute:

```
Step 1: sample S_i' ~ d
Step 2: evaluate K(S_i', S u S_i')
        H = K(S_i',S_i') - K(S_i',S) L^{-T} L^{-1} K(S_i',S)^T
        S_i, L_i^{-1} = reject(H, S_i')
Step 3: M = L^{-T} L^{-1} K(S, S_i)         (precompute, |S| x nacc)
        for each block R of b rows over all NM rows:
            evaluate K(R, S u S_i)
            G = (K(R,S_i) - K(R,S) M) L_i^{-T}
            d(R) -= SquaredRowNorms(G)
        L^{-1} <- [[ L^{-1},          0      ],
                   [ -L_i^{-1} M^T,   L_i^{-1}]]
        d = max{d, 0}
        S = S u S_i
```

Here `d` is the residual diagonal (`dvec` in the code) that drives the
sampling, `b` is the block size (`BLK` in the code), and `nacc` is the
number of pivots accepted in the round.

The matrix `M` is computed once per round, before the row loop,
and is used both for the `d` update in the row loop
and for the `L^{-1}` update after the row loop.

## The kernel matrix

`K` is generated by a Gaussian kernel function with constant bandwidth
acting on a dataset of spatiotemporal samples.
Each sample index refers to a point in space-time; the kernel compares
two samples by taking the squared difference over a delay window of
`Nq` consecutive time samples.

The kernel matrix is never fully formed.
It is evaluated in blocks by `compute_kblock` in the precision needed.

## Program structure

The code is a single SPMD program with one MPI rank per GPU.
Each rank controls one GPU device, drives it through a private CUDA stream,
and communicates with the others through NCCL collectives.
MPI is used only for the initial setup, a per-round barrier, and the final
gather of results.

A single-GPU run is the `Ndevs = 1` case, launched with one MPI rank.

## Data distribution

There are two independent data distributions across the `Ndevs` devices.

- **1D row block** for the kernel matrix `K`.
  Device `j` is responsible for the global rows
  `[j*Nrows, (j+1)*Nrows)` of the kernel matrix, where
  `Nrows = NM / Ndevs`.
  All Step-3 regeneration work is partitioned this way.
- **1D column block** for `L^{-1}`.
  Device `j` owns global columns
  `[j*cblk, (j+1)*cblk)` of `L^{-1}`, where `cblk = rmax / Ndevs`.
  The blocks are contiguous, not cyclic.

Everything else that persists is replicated on every device: the input
dataset, the residual diagonal `d`, the pivot list `S`,
and the small `b x b` dense buffers of the accept/reject check.

## Input

The problem is defined by the input data file and a set of compile-time
parameters at the top of `main`; there are no command line arguments.

The code reads the input dataset from an HDF5 file in single precision.
This dataset supplies the spatiotemporal data the Gaussian kernel acts on.
The kernel function is defined by its bandwidth and delay window `Nq`.
The remaining code parameters include the number of rounds `Nrounds`,
the block size `BLK`, the rejection tolerance `tol`
and the number of GPU devices `Ndevs`.

The code checks that `Ndevs` divides the number of samples,
the number of spatial points, and `rmax`.

## Output

The code writes two HDF5 files.

- One file with the accepted pivot set `S`, containing the `Nr`
  global indices in acceptance order.
- One file with the `Nr x Nr` lower triangular inverse Cholesky factor
  `L^{-1}`, flattened in column major order, in double precision.

Because `L^{-1}` is distributed across the devices in column blocks,
it is assembled on rank 0 by an MPI gather of those blocks, which
reconstructs the full column major matrix before writing it.

The run also prints a per-round report (pivots accepted,
cumulative rank, relative trace norm error)
and the total run time.

## CUDA kernels

- `initialize_rstate`, `initialize_dvec` — set up the per-thread
  RNG state and the initial residual diagonal.
- `propose_block` — Step 1: sample `BLK` candidate pivots from `d`.
- `compute_kblock` — evaluate a row major kernel block for a given set
  of rows against the pivots plus a tail index set.
- `extract_H` — pull the `b x b` residual submatrix out of the
  proposal block.
- `rejection_sample` — the accept/reject check over `H`,
  returning the accepted pivots, their positions, and `L_i^{-1}`.
- `gather_cols` — select the accepted columns of a dense block.
- `repack_M` — reorder and cast the gathered `M` blocks into the layout
  the row loop expects.
- `update_diag_block` — subtract the squared row norms of one `G` block
  from `dvec`, clamped at zero.
- `append_Linv_overlap`, `append_Linv_diag` — write the new block-row
  `[ -L_i^{-1} M^T | L_i^{-1} ]` into the owned column block of `L^{-1}`.
- `compute_dsum` — reduce `d` to the round's error estimate.

Dense linear algebra is performed via cuBLAS functions.

## Per-round work

**Step 1 — propose.** `propose_block` draws `Sprime`, replicated.

**Step 2 — rejection.**
1. `compute_kblock` evaluates `K(S_i', S u S_i')`, replicated on every
   device.
2. `extract_H` takes the `K(S_i',S_i')` block out of it.
3. Each device forms its local share of `P = L^{-1} K(S,S_i')` over its
   owned columns, then `AllReduce(P)` makes it replicated; a
   symmetric-rank-update then applies `H -= P^T P`.
4. `rejection_sample` yields the accepted pivots `S_i`, their count
   and `L_i^{-1}`.

**Step 3 — update.**
1. `gather_cols` extracts `Q` as the accepted columns of `P`; no new
   product is needed, since `S_i` is a subset of `S_i'`.
2. Each device forms its row block of `M` from its own columns of
   `L^{-1}` and `Q`.
3. `AllGather(M)`, then `repack_M` into the replicated float `M`.
4. Row-block loop over this device's `Nrows` rows in steps of `rblk`:
   evaluate `K(R, S u S_i)`; form `T = K(R,S_i) - K(R,S) M`; form
   `G = T L_i^{-T}`; then `update_diag_block` on `dvec(R)`.
5. `append_Linv_overlap` and `append_Linv_diag` write the new block-row
   of `L^{-1}`. This is done locally: `M`'s rows are partitioned exactly
   like `L^{-1}`'s columns, so each device needs only its own row block
   of `M`.
6. Append the accepted pivots to `Spiv`.

**Finalize.** `AllGather(dvec)` replicates the residual
diagonal and `compute_dsum` then records the round error.

There are three collectives per round: `AllReduce(P)` and
`AllGather(M)`, both small and in double precision;
`AllGather(dvec)`, one float slice per device.
Everything else is performed locally.

## Design choices

- **1D column block distribution.**
  Matrix `L^{-1}` is distributed by contiguous column blocks,
  not cyclically.
  As a result, early rounds leave the higher-numbered devices idle
  for the `L^{-1}` products, until the pivot count exceeds `cblk`.
  The work done while `L^{-1}` is imbalanced is a small fraction
  of the overall work.
- **Mixed precision.**
  Both single and double precision is used in the code.
  `L^{-1}`, the proposal block, `P`, `Q`, `M` and the accept/reject check
  are done in double precision.
  The dominant Step-3 work is done in single precision.
  The memory saved by not storing a full factor matrix is what makes
  the double precision affordable.
- **Row major buffers & cuBLAS.**
  Kernel blocks are stored in row major order.
  To hand them to cuBLAS without having to make transposed copies,
  we reinterpret them as column major by selecting the appropriate
  leading dimensions and cuBLAS transpose flags.
- **Repacking `AllGather(M)`.**
  In the `AllGather` of `M` each device contributes a `cblk x nacc`
  row block, and the blocks are then concatenated by rank.
  This is not the column major layout the row loop needs, so
  `repack_M` converts and casts it once per round.

## Build and run

The used compile and run commands are in the comment header of
`arpclm.cu`.
They depend on the hardware and available library paths.

The number of MPI ranks used to run the code must be equal to the
compile-time constant `Ndevs` set in the code.
